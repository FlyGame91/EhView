# EhView — ExHentai / E-Hentai 桌面浏览与下载工具

一个本地桌面软件（Electron），把 E-Hentai / ExHentai 的常用操作整合在一起，并补齐原站缺失的能力。

## 启动

双击 `release\EhView\启动 EhView.bat`，或直接运行 `release\EhView\EhView.exe`。

## 首次使用（必须登录）

ExHentai 的绝大多数接口都要求登录，未登录调用没有意义（软件也只在登录后才调用相关接口）。

1. 打开「设置 → 账号」，点 **打开 Chrome 登录**。
2. 在弹出的 Chrome 窗口里完成 E-Hentai 登录（Cloudflare 验证由真实浏览器自动通过）。
3. 登录后，同一个窗口会打开 `https://exhentai.org/`，等待它跳转完成（这一步会拿到 ExHentai 的 igneous 凭证）。
4. 回到软件，点 **检测登录状态**。软件会自动关闭它启动的 Chrome、读取并解密登录 Cookie，然后保存。
5. 若自动读取失败，可用「手动导入 Cookie」：从浏览器扩展（如 Cookie-Editor）导出 JSON 粘贴进来，或粘贴 `ipb_member_id=...; ipb_pass_hash=...`。

> 说明：软件读取 Cookie 使用的是独立 Chrome 配置目录（`%APPDATA%\EhView\chrome-profile`），不会动你日常浏览器的登录数据。

## 功能对照（原始痛点 → 实现）

| 痛点 | 本软件的实现 |
| --- | --- |
| 1. 多页查看器图片不占满页、长图看不全 | **内置阅读器**：左右方向键/空格翻页、鼠标左右区域点击翻页、适应宽度/适应高度/原始大小三种缩放、连续滚动模式、全屏、预加载下一页、记住阅读进度 |
| 2. 打包下载步骤繁琐 | 详情页 **一键下载原始归档**：自动走完 archiver 生成流程并直接下载到设置好的目录；支持「原始文件 / 重新采样」两种规格 |
| 3. 种子 seeds=0 没有提示 | **种子面板**会解析每个种子的做种/下载数，`seeds=0` 时用红色警告标出「无人做种，此种子无法下载」 |
| 4. 看过的图没有本地缓存 | **图片缓存目录**（可随时在设置里改）：所有图片经本地缓存协议加载，看过的图离线也能看；可查看占用、一键清空 |
| 5. 站点收藏没有标签/关键词搜索 | **本地库**：把图集加入本地库时自动保存全部标签，支持关键词 + 多标签组合筛选、按加入时间/评分/页数排序 |
| 6. 代理 + 货币信息 | 两种联网方式：**代理**（`http://` / `socks5://`）或 **HTTP/3 直连**（走安全 DNS，无需代理）；顶栏常驻显示 **Hath / GP / Credit**（每 5 分钟自动刷新） |
| 7. 必须先登录 | 登录后才启用收藏、归档、货币等需要鉴权的功能；未登录时只用公开接口（搜索、图集元数据、图片） |

## 目录结构

```
D:\EhView\
├── release\EhView\          打包好的可执行程序
├── electron\                 主进程（网络、解析、缓存、下载、Cookie）
├── src\                      界面（React）
├── data\                     默认下载目录与图片缓存（可在设置中修改）
└── README.md
```

## 设置项

- **账号**：登录 / 检测 / 手动导入 Cookie / 退出
- **网络**：连接方式（代理 / 直连 HTTP/3）、代理地址、安全 DNS（DoH）服务器、站点（ExHentai / E-Hentai）、User-Agent，以及「检测直连」自检
- **目录**：下载目录、图片缓存目录（均可选择并随时修改）
- **图片缓存**：启用开关、占用统计、清空
- **阅读器**：默认缩放模式、预加载页数

## 快捷键（阅读器）

- `←` / `→` / `空格`：翻页
- `Home` / `End`：首页 / 末页
- `F`：全屏
- `W`：切换 适应宽度 / 适应高度
- `Esc`：返回图集

## HTTP/3 直连（无需代理）

设置里把「连接方式」切到 **直连（HTTP/3，无需代理）**，填一个**境外** DoH 服务器，点「保存设置」后再点「检测直连」即可。

原理（实测结论）：

- 该站点的 TCP 443 连接会因为 TLS ClientHello 里的 SNI 命中关键词被重置（同一可用 IP 上，`SNI=www.cloudflare.com` 握手成功，`SNI=e-hentai.org` 立刻被 RST），所以改 hosts、换 IP、换系统 DNS 都没用。
- 但 **UDP 443 的 QUIC 没被拦**。Chromium 只有在同时拿到「真实 A/AAAA」和「HTTPS(type 65) 记录里的 `alpn=h3`」时才会尝试 HTTP/3 —— 这就是必须用 DoH、且必须开 `enableAdditionalDnsQueryTypes` 的原因。
- DoH **必须选境外且未被墙的**端点。国内阿里/腾讯 DoH 的上游同样被污染，返回的是 Facebook/Dropbox 段假 IP，填了等于没填。

## 已知限制

- **Cloudflare**：E-Hentai 论坛域的验证只对真实浏览器放行。因此软件不自己登录，而是调用系统 Chrome 完成登录（已实测：真实 Chrome 6 秒通过，自动化环境无法通过）。
- **ExHentai 的 igneous**：由 forums 的 remoteapi 下发，需在登录后的浏览器里访问一次 `exhentai.org` 才会生成；软件在登录流程里已自动带你走这一步。
- 归档下载链接由服务端异步生成，偶尔需要等待几秒；软件会自动重试。
